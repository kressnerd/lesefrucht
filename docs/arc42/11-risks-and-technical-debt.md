# 11. Risks and Technical Debt

## Risks

| ID | Risk | Probability | Impact | Mitigation |
|---|---|---|---|---|
| R-001 | Passage identity or citation bounds drift between indexing and `read_passage` (extraction, normalization or chunk offsets not reproducible), so citations point at the wrong span and re-indexing rewrites the index each run. | Medium | High | Passage identity derived from content hash + chapter + ordinal + offsets; `read_passage` verifies the cited span's sha256 against the stored hash; a golden test indexes the fixture library twice and asserts identical ids, offsets and texts. |
| R-002 | A partially applied commit across SQLite, Tantivy and usearch leaves a citation pointing at a passage the index no longer holds. (ADR-0001 "Bad, because three stores have no shared transaction".) | Medium | High | Single writer facade with a fixed commit order; a startup repair pass marks inconsistent editions `invalidated` and re-indexes them; the edition becomes `indexed` only after all three writes succeed. |
| R-003 | A full rebuild re-embeds every passage, so recovery time and endpoint cost grow with the library. (ADR-0001 "Bad, because a rebuild re-embeds every passage".) | Medium | Medium | The content-hash skip avoids needless re-embedding; a rebuild is a deliberate operation, not a routine step; cost is bounded by the library and the configured endpoint. |
| R-004 | The two evidence thresholds are tuned on one corpus and behave differently on the real library, producing either empty results or noise. (ADR-0001 "Bad, because the two score scales must be tuned together".) | Medium | Medium | Thresholds are configuration; assertions in the suite are on order, counts and the `short` flag rather than on score values; the fixture library carries deliberate score gaps for both paths. |
| R-005 | In-memory MCP sessions are lost on restart, so a connected agent fails until it re-initializes. (ADR-0002 "Bad, because sessions live in memory".) | Medium | Low | Session failures surface as protocol errors, not as `no_evidence`; clients re-initialize on session-not-found; the e2e driver creates one client per scenario. |
| R-006 | The MCP listener has no authentication, so exposing it beyond loopback would let any local or remote client retrieve book text. (ADR-0002 "Bad, because a network listener without authentication".) | Low | High | Default bind is loopback; chapter 2 records the exposure constraint; exposing the service is a separate decision that must add authentication first. |
| R-007 | SSE framing on the Streamable HTTP response introduces a failure mode a stdio pipe does not have, and a hand-written client would mis-parse it. (ADR-0002 "Bad, because SSE framing adds a failure mode".) | Low | Medium | The server and the e2e driver both use the SDK's transport; no scenario reads a raw response body. |
| R-008 | The PDF extractor's reading order on real books differs from the fixture PDFs, producing odd chunk boundaries or `extraction_failed`. | Medium | Medium | The failure is explicit and visible in index status; EPUB is the preferred format in the selection order; PDF behaviour is revisited when real-library ingestion is exercised. |
| R-009 | The configured embedding endpoint is unavailable or answers with a different dimension, blocking indexing. | Medium | Medium | Dimension validation fails the edition with `embedding_failed`; bounded retries with backoff; readiness reports failed editions rather than pretending the index is complete. |
| R-010 | The host has no usable Rust toolchain: `rustup show` reports default host `x86_64-unknown-linux-musl` with no installed toolchain and no default (observed 2026-10-27), so `rustc`/`cargo` fail with "could not choose a version"; a remembered pin file would not help. | Medium | Medium | Exactly one pin mechanism: the Nix flake devShell provides `nixpkgs#rustc`, `nixpkgs#cargo` and `nixpkgs#calibre`; there is no `rust-toolchain.toml`. The setup task records the resolved versions in `design.md` (Version Freshness). |
| R-011 | The library generation cache makes a library change invisible for the cache interval, so a stale index is not detected promptly. | Low | Low | The cache is short and configurable (`index.generation_cache_ms`); the stale scenario runs with the cache disabled; the freshness bound is the authoritative limit. |
| R-012 | The `calibredb` CLI drifts between calibre releases: the `--for-machine` field set, the `--fields all` requirement, the export flags or the ` & ` author-join convention change, and discovery or export breaks. (ADR-0002 has no bearing here; this is the cost of the documented-CLI decision, T8.) | Medium | Medium | Tests run the real `calibredb` (no twin), so drift fails the suite immediately; an unparsable or non-zero invocation is `source_unreachable`, never a partial listing; the devShell and the e2e image share one pinned nixpkgs revision; the setup task records the resolved calibre version. |
| R-013 | `calibredb` is not installed on a host (observed on the development host on 2026-10-27), so the product and the test suite cannot start. | Medium | Medium | The Nix devShell and the product image install the `calibre` package; startup fails with a named configuration error when `library.calibredb_binary` cannot be executed, never with a stale empty index. |
| R-014 | The cucumber runner configuration is written against the wrong API and silently selects no scenarios, so every reported PASS is unverified. | Low | High | The runner uses `cucumber::cli::Opts::<_,_,_>::parsed()` and `run_and_exit("givn")`, `--name` is never combined with `--tags`, and `./run-tests.sh --prove-strictness` must exit non-zero on an unbound step before any scenario is implemented. Mitigated in the design (Test Runner); the proof is a task deliverable. |

## Technical debt

| ID | Item | Impact | Plan to address |
|---|---|---|---|
| TD-001 | Three derived stores with no cross-store transaction; correctness depends on commit ordering, the single-writer facade and the startup repair pass. | A crash can require re-indexing one edition; a bug that bypasses the facade can corrupt the index silently. | Keep the facade the only writer; repair covers the crash case; a later change may add a manifest per edition if repair proves insufficient. |
| TD-002 | A rebuild re-embeds all passages; there is no incremental or resumable rebuild. | Recovery is proportional to library size and endpoint cost. | Accept for a single-owner library; revisit if a rebuild becomes routine. |
| TD-003 | usearch is a native dependency with its own persistence rules; deleted passages need compaction to reclaim space. | Index files can grow after many re-index operations; native build requirements on the host. | Compaction on a deletion threshold; the pin lives in `Cargo.lock` and the Nix shell. |
| TD-004 | The MCP listener has no authentication and no TLS; it is safe only on loopback. | The service cannot be shared or exposed as is. | An authentication decision is required before any non-loopback bind; recorded as a constraint in chapter 2. |
| TD-005 | Protocol revisions follow the `rmcp` release cadence. | An SDK upgrade can change negotiated capabilities and the e2e client. | Upgrade deliberately with the e2e suite as the check; the transport choice is ADR-0002. |
| TD-006 | The test and coverage pipeline depends on host-provided tools (`grcov`, `llvm-tools`, podman) resolved from nixpkgs. | A host change can break `./run-tests.sh` or `./measure-coverage.sh` without a code change. | Pin the tool set in the Nix shell and record it in the setup task. |
| TD-007 | AZW3 and MOBI editions fail explicitly and are therefore unsearchable. | Part of a real library contributes no evidence; the failure is visible but the gap is real. | Adopt `rbook`'s MOBI/AZW3 reader in the change that makes those formats supported; the state machine already carries the reason. |
| TD-008 | Model-based query expansion is not implemented; expansion is deterministic only. | Cross-language recall depends on the configured synonym map until the glossary and model expansion arrive. | Glossary expansion lands with `glossary-expansion`; model expansion remains a configuration option with a deterministic fallback. |
| TD-009 | The viewer link (`calibre://show-book/<library>/<work>`) opens the edition but carries no position, so a reader who follows a citation navigates to the character span by hand. Character offsets are authoritative and `read_passage` proves the span; only the position-aware opening (`calibre://view-book/...?open_at=...`) is deferred. (Design-review decision D3; ADR-0002 is unaffected.) | The `reader--researcher` criterion "exact position" is met for the agent (the span is exact) but not yet for the human viewer in one click. | Resolve in the change that first renders a reader-facing surface, and not later than the first change that owns a viewer integration. The position-bearing scheme is already documented (`calibre://view-book/<library>/<id>/<FORMAT>?open_at=<location>`); what is missing is a verified mapping from the product's character offsets to calibre's viewer locator. Resolution condition: such a mapping exists and is verified against a rendered viewer (or the project ships its own viewer route), and the citation gains an `open_at` field whose scenario asserts the cited span opens. Until then `viewer_url` stays edition-only. |
| TD-010 | `calibredb` machine output stringifies the author list with ` & `, so the split is a convention, not a structured field. | An author whose name contains ` & ` is split incorrectly; author scope and the citation's `authors` array can be wrong for that book. | Revisit when calibre exposes structured authors in machine output, or when a real author name triggers it; the fixture library includes an ` & ` author only once the split rule is tested. |
